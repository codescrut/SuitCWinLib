SuitCLib: Contains Windows SuitCLib, a port of SuitC to VS C++
Demo: Contains C# demo code for using the library
Example: A compiled and running example

Note: The project should be compiled in release mode (For unknown reason the debug version is broken).

Compiled and tested in VS2022

Release notes
=============

0.9.0.11
- Fix stack buffer overrun (0xC0000409, STATUS_STACK_BUFFER_OVERRUN) that killed
  the host process. Root cause: TRICKS entries that convert_tree_to_quirk never
  filled were read anyway, because a QUIRKD's [il,ih] board range can reach past
  what its QUIRKH header wrote. TRICKS.ns is an 8 bit field, so the stale value
  (190 in the reported case, against a legal maximum of 4) was then used to
  index best_result.tricks[], perc[] and best_N[] -- all NCARDS+1 long, two of
  them on the stack -- hundreds of entries past their end. That destroys the /GS
  cookie, and the resulting __fastfail cannot be caught by SEH, VEH or
  SetUnhandledExceptionFilter, so the host could neither log it nor take a dump.
  bump_quirkh now fills every TRICKS array it hands out with 0xff, and
  evaluate_best_results refuses the call if it reads a trick count above
  ntricks, instead of computing a result over stale entries
- Fix best_N being one entry short: it is indexed by trick count, which runs
  0..ntricks inclusive, so a legal maximum of NCARDS already overran it
- Bound every walk over the NODE tree. bnode[]/lnode[]/tnode[] hold NPLIES+1
  entries and the depth counter was incremented with no check, so a malformed
  tree could walk off the end of a stack array. Guards in use_suit_entries,
  delete_tree, delete_board, copy_tree, build_selected_tree, check_ew_plays,
  determine_trick_count, fold_tree, fold_ew_tree, fold_ns_tree, select_ew_plays,
  select_ns_plays, convert_tree_to_quirk and print_tree
- Fix pool exhaustion handing out out-of-pool entries: bump_index/bump_node/
  bump_quirkd/bump_quirkh printed a warning, left next* one past the end of the
  malloc'd block and carried on, so the next allocation wrote outside the pool.
  The last entry of each pool is now a sentinel and the call is refused
- bump_quirkh no longer calls exit(99) when the TRICKS allocation fails; a
  library must not take the host process down. Its sentinel buffer is reserved
  at start-up, where the failure can still be reported as an error
- Pool exhaustion, depth overflow and an out-of-range trick count now return an
  error document instead of continuing over a tree that cannot be trusted
- Fix the version resource: the binary FILEVERSION/PRODUCTVERSION fields had
  been left at 0,9,0,5 since that release, so Windows Error Reporting and the
  Application event log named 0.9.0.5 for every build since -- which is why the
  crash report for this bug cited a version nobody was running. Only the
  StringFileInfo text (what Explorer shows) had been kept up to date

0.9.0.10
- Fix access violation (0xC0000005) on empty game trees: -wv/-ev (or -wm/-em)
  combined with played tricks can filter every board away, leaving plies with no
  nodes and a selected tree with no descendants. Guards in build_selected_tree,
  create_ply1-4 and use_suit_entries; an error document is returned instead
- Release memory on both create_tricks failure paths

0.9.0.9
- Fix malformed JSON on SuitC error/success output

0.9.0.8
- Fix native heap leak (~430 KB per call_suitc) and a double-free crash;
  export suitc_free_memory() so hosts can release the internal pools
- Platform-aware wchar_t marshalling (2 bytes on Windows, 4 on Linux/macOS)
- Fix memory leaks in evaluate_mp_scores, limit_matchpoint_nodes, and limit_quirk
  (leaked KB to MB per call; accumulated to GB over long sessions)

0.9.0.7
- Fix crash when leader has no cards after played tricks (transfer lead to partner)
- Do not change leader based on trick winner; caller determines who leads

0.9.0.5
- Added played cards as command line parameter
- Updated to latest version from Gerrit van der Velde
